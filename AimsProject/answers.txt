1. Method Overloading - Compare to an array parameter. What do you prefer in this case?
- Varargs (variable-length arguments) is generally preferred in this case. It provides a cleaner and more flexible syntax.
 With varargs, the caller can simply pass multiple arguments separated by commas (e.g., addDigitalVideoDisc(dvd1, dvd2, 
dvd3)) without having to explicitly create an array object first (like new DigitalVideoDisc[]{dvd1, dvd2}). 

2. Is JAVA a Pass by Value or a Pass by Reference programming language?
- Java is strictly Pass by Value. 

3. After the call of swap(jungleDVD, cinderellaDVD) why does the title of these two objects still remain?
- Because Java is pass-by-value. When calling the swap method, Java passes a COPY of the object references (the memory 
addresses). Inside the swap method, we are only swapping these copied references (o1 and o2), making them point to 
different objects. However, the original references in the main method (jungleDVD and cinderellaDVD) remain completely 
unchanged and still point to their original objects.

4. After the call of changeTitle(jungleDVD, cinderellaDVD.getTitle()) why is the title of the JungleDVD changed?
- Even though Java passes the reference by value (a copy of the reference), this copied reference still points to the 
EXACT SAME object in the memory heap. By calling the setter method (dvd.setTitle(title)) using this reference, we directly
modify the internal state (the title attribute) of the actual object that both the original and copied references are 
pointing to.

5. Write a toString() method for the DigitalVideoDisc class. What should be the return type of this method?
- The return type of the toString() method must be `String`. It overrides the default toString() method from the Object 
class to provide a string representation of the DVD's details.
