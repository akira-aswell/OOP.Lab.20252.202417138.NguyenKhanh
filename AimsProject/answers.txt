2. (Page 8) Polymorphism with toString() method. Observe what happens and explain in detail.
- When iterating through the ArrayList<Media> and calling m.toString(), the system prints the specific details of each actual object type (Book, CD, or DVD). This is Polymorphism (Dynamic Binding). Even though the reference variable 'm' is of type 'Media', Java determines the actual object type at runtime and calls the overridden toString() method belonging to that specific subclass.

3. (Page 9) Suppose we are taking this Comparable interface approach:
- What class should implement the Comparable interface?
The Media class should implement Comparable<Media>.
- In those classes, how should you implement the compareTo() method?
We would implement public int compareTo(Media other) and compare their attributes (e.g., title, then cost).
- Can we have two ordering rules of the item if we use this Comparable interface approach?
No. The Comparable interface only defines ONE "natural ordering" for a class. If we want multiple sorting rules (by title-cost and by cost-title), we MUST use the Comparator interface.
- Suppose the DVDs has a different ordering rule from the other media types. How would you modify your code?
We would create a separate Comparator specifically for DigitalVideoDisc, or override the compareTo() method specifically inside the DigitalVideoDisc class to prioritize title, then length, then cost.
